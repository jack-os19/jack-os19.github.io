Aanpak

Het ontwikkelproces

Van probleem naar werkende oplossing, stap voor stap.

1

Probleem identificeren

Audiobestanden werden opgeslagen in een map zonder structuur. Geen manier om te achterhalen welke node wat had opgenomen, wanneer, of hoe lang de opname duurde.

2

Database ontwerpen

Een ERD ontworpen in dbdiagram.io met drie tabellen: nodes, recordings en node_status. Relaties gedefinieerd met foreign keys.

3

Technologiekeuze

Onderzoek gedaan naar PostgreSQL, MariaDB en SQLite. Gekozen voor SQLite vanwege eenvoudige implementatie. SQLAlchemy abstraheert de database, dus overstappen is later één connection string wijzigen.

4

Implementatie

SQLAlchemy models, Pydantic v2 schemas en CRUD endpoints gebouwd in een gestructureerde FastAPI applicatie met routers. Getest via Swagger UI.

Uitdagingen

Problemen en oplossingen

Placeholder mappen vs. Python bestanden

Python importeerde lege placeholder mappen in plaats van mijn models.py en schemas.py bestanden. Oplossing: mappen verwijderen. Les: Python's importsysteem geeft mappen prioriteit boven bestanden met dezelfde naam.

Verouderde tutorials

Online tutorials gebruikten Pydantic v1 syntax (orm_mode, .dict()). Moest zelf uitzoeken dat de nieuwe equivalenten ConfigDict(from_attributes=True) en .model_dump() zijn.

Import paden

Absolute imports werkten niet binnen de package structuur. Geleerd dat relatieve imports (from ..db import Base) nodig zijn binnen dezelfde package.

Database switch

Van PostgreSQL naar SQLite overgestapt. Dankzij SQLAlchemy's abstractielaag was dit een connection string aanpassen en een paar regels code wijzigen.
